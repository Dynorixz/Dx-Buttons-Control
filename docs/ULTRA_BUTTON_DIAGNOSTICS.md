# Galaxy Watch Ultra: диагностика нижней кнопки

Исторический отчёт сборки 1.1.1-diagnostics. После получения фотографий gpio_keys / isVirtual=false и указания модели SM-L705 подготовлен [новый профиль 1.1.2-ultra-test](ULTRA_GPIO_PROFILE_1.1.2.md); сведения ниже отражают предыдущий этап диагностики.

Дата: 2 ноября 2026. Сборка: **1.1.1-diagnostics**, versionCode 4. Это подписанная диагностическая сборка; поддержка конкретного Galaxy Watch Ultra клиента ещё не подтверждена аппаратной проверкой.

## Что установлено

В предоставленном сообщении известны только KEYCODE_STEM_PRIMARY (264) и scanCode 580. Имя InputDevice, descriptor, deviceId, source и isVirtual на часах клиента неизвестны. Часы не подключены к ADB, mDNS не обнаружил устройств. Пользователь уточнил, что часов у него нет: фото прислал клиент.

Старое сообщение объединяло разные причины: отказ ButtonSafety, отсутствие descriptor и отрицательную проверку `device?.virtual == false`. Найдена и воспроизведена в тесте гонка: асинхронный кэш ещё не содержит InputDevice при UP, поэтому null ошибочно приводит к тому же отказу, что виртуальное устройство. Это подтверждённый дефект обработки отсутствующих метаданных, но не доказательство причины на Ultra клиента.

Теперь после UP калибровка ожидает результат асинхронного чтения до 1500 мс. onKeyEvent при этом не блокируется и пропускает события системе. Если данные так и не получены, привязка не создаётся; причина остаётся DEVICE_INFO_PENDING / DEVICE_NOT_FOUND / DEVICE_INFO_READ_FAILED, а не объявляется виртуальным вводом. При замене или отключении InputDevice устаревший результат не может разрешить привязку.

## Проверки безопасности

Новых аппаратных профилей без подтверждения не добавлено. Для STEM_PRIMARY остаётся прежнее исключение: **pmic_resin + scan 580/114 + непустой descriptor + совпадающий deviceId + isVirtual=false**. Сам код 264 по-прежнему защищён. Home/Power, неизвестные источники STEM_PRIMARY и виртуальные устройства не разрешаются. Для прежних допустимых Back/STEM_1/STEM_2/STEM_3 сохранены существующие правила.

Калибровка, сохранение настроек и обработка нажатий используют общие правила ButtonSafety. Сохранённая привязка сверяется с текущими keyCode, scanCode, descriptor и именем устройства. Режим перехвата для STEM_PRIMARY не включается.

## Как клиенту получить данные

1. Установить `dx-buttons-control-1.1.1-diagnostics-wear-release.apk`. Подпись соответствует прежнему release 1.1.0; для него переустановка со сбросом не нужна. Debug имеет другую подпись. Перед удалением любой версии настройки нужно экспортировать за пределы данных приложения.
2. Включить службу Dx в специальных возможностях. Открыть **Настройки → Кнопка и циферблат → Определить кнопку**.
3. В течение 12 секунд один раз коротко нажать и отпустить именно нижнюю Back. Кнопка может штатно закрыть экран приложения — события по-прежнему пропускаются системе.
4. Вернуться в Dx и открыть **Отчёт кнопки** на экране настройки кнопки. Нажать **Поделиться JSON** либо **Сохранить JSON**. Если на часах нет подходящих обработчиков этих действий, прислать фотографии всех данных отчёта.
5. До нового отчёта сохранить предыдущий: приложение хранит только последнюю калибровку. Для сравнения полезен отдельный отчёт короткого нажатия верхней Home, если её события вообще доступны. Удерживать Power или проверять экстренные сочетания не требуется.

В отчёте нужны: appVersion, manufacturer/model, Android/API/buildDisplay, полная пара DOWN/UP, keyCode/scanCode, event.deviceId/source, InputDevice.id/name/descriptor/sources/isVirtual, состояния метаданных на DOWN и UP и после ожидания, bindingAllowed, hardwareAllowed, sequenceIssues и rejections. Один скрин только с 264/580 недостаточен.

| Причина | Значение |
|---|---|
| STEM_PRIMARY_DEVICE_UNVERIFIED | Фактическое имя отличается от подтверждённого pmic_resin; нужен анализ источника на Ultra |
| STEM_PRIMARY_SCAN_UNVERIFIED | Scan отличается от уже подтверждённых 580/114 |
| VIRTUAL_DEVICE | InputDevice существует, но Android возвращает isVirtual=true; это отдельный отказ |
| DEVICE_INFO_PENDING | Чтение не завершилось за отведённое время; isVirtual неизвестен |
| DEVICE_NOT_FOUND / DEVICE_INFO_READ_FAILED | InputManager не нашёл устройство либо вернул исключение |
| DESCRIPTOR_MISSING / DEVICE_ID_MISMATCH | Нет устойчивой идентичности устройства либо данные относятся к другому id |
| DOWN_MISSING / UP_MISSING / PAIR_MISMATCH / EVENT_CANCELED | Не подтверждена целая согласованная пара событий |

Отчёт сохраняется локально после калибровки и переживает закрытие UI. Восстановление старого отчёта не создаёт candidate и не включает привязку: для подтверждения кнопки нужна новая калибровка. Экспортируются только сведения о кнопке и версии устройства, без текстов экранов, переписок, списка приложений или настроек пользователя.

## Калибровка и назначение действия

Если все проверки пройдены, пользователь отдельно нажимает **Это нижняя кнопка**. Затем в карточке жеста выбирает, например, вибрацию. **Проверить действие** проверяет только команду; физический жест нужно отдельно выполнить на включённом экране. Двойной и тройной проверяются только на подтверждённом циферблате. Одиночный Back должен сохранять штатное поведение.

Если проверка отклонена, принудительное разрешение 264 не предлагается. После получения JSON можно добавить узкий профиль по подтверждённым данным или установить, что прошивка не позволяет надёжно отличить нижнюю кнопку от защищённой.

## Проверки разработки

148 JVM-тестов прошли, без ошибок. Из них 30 новых проверяют конкретные причины отказа, холодный кэш, ожидание и таймаут метаданных, отключение/замену устройства, отсутствие устаревшей записи, согласованность пары, JSON отчёта, сохранение допустимой привязки с назначенным действием и отказ runtime при другом/виртуальном устройстве. Сохранены прежние тесты жестов и ActionExecutor.

Подписанный APK реально собран через assembleRelease и lintRelease: 0 ошибок, 14 предупреждений. Размер — 3 263 471 байт, подпись v2 и выравнивание проверены, сертификат совпадает с release 1.1.0. Готовые APK и полные исходники доступны отдельно в Releases; пути рабочего компьютера автора не требуются. Для повторной release-сборки:

```powershell
.\scripts\BuildRelease.ps1 -SigningFile 'C:\Private\dx-release.properties' -JavaPath 'C:\Android\jdk-17' -SdkPath 'C:\Android\Sdk'
```

Закрытый ключ хранится отдельно от проекта. Он и пароль в ZIP/облака не включаются. Gradle Wrapper и все исходники/ресурсы входят в ZIP; публичные зависимости закреплены в Gradle и скачиваются при первой сборке, Android SDK устанавливается отдельно.

Данные устройств в unit-тестах — контролируемые тестовые значения, не измерения с Galaxy Watch Ultra. Проверка калибровки, назначения действий и жестов на реальных часах клиента остаётся необходимой.

## При доступном ADB у клиента

```powershell
adb -s <IP:PORT> logcat -v threadtime -s DxButtonCalibration
```

Затем выполнить физическое короткое нажатие во время калибровки. Калибровочные сообщения включены и в подписанном release APK. `adb shell input keyevent 264` создаёт синтетический ввод и не заменяет физическую проверку. Не включайте другие службы фильтрации клавиш на время проверки.

Официальные контракты: [InputDevice.isVirtual](https://developer.android.com/reference/android/view/InputDevice#isVirtual()), [KeyEvent.getDeviceId](https://developer.android.com/reference/android/view/KeyEvent#getDeviceId()), [AccessibilityService.onKeyEvent](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService#onKeyEvent(android.view.KeyEvent)).
