# Установка и первый запуск

## Выбор APK

Скачайте отдельный `dx-buttons-control-1.1.2-ultra-test-wear-release.apk` из [релиза](https://github.com/Dynorixz/Dx-Buttons-Control/releases/tag/v1.1.2-ultra-test). Это подписанный установщик для часов Wear OS, versionCode 5. ZIP — исходники; debug artifacts GitHub Actions — результаты проверки сборки с другой подписью.

**1.1.2 — предварительная сборка для проверки Ultra SM-L705.** Новый APK на часах клиента ещё не испытывался. Для других устройств смотрите [совместимость](COMPATIBILITY.md).

## Беспроводной ADB

1. На часах включите параметры разработчика и «Беспроводная отладка».
2. Подключите компьютер и часы к одной сети.
3. Используйте порт экрана сопряжения для `adb pair`, а порт основного экрана отладки — для `adb connect`.

```sh
adb pair <WATCH_IP>:<PAIRING_PORT>
adb connect <WATCH_IP>:<CONNECTION_PORT>
adb devices -l
adb install -r dx-buttons-control-1.1.2-ultra-test-wear-release.apk
adb shell am start -W -n com.dynorixz.buttonscontrol/.MainActivity
```

При нескольких устройствах добавьте `-s <WATCH_IP>:<CONNECTION_PORT>` после `adb`. ADB нужен для установки и диагностики, не для обычной работы.

## Включение и калибровка

1. В специальных возможностях вручную включите **«Dx · Управление нижней кнопкой»**. При сообщении об ограниченных настройках используйте штатный экран Android.
2. В Dx откройте **Настройки → Кнопка и циферблат → Определить кнопку**.
3. Во время 12-секундной проверки коротко нажмите и отпустите **нижнюю Back**. Системное Back может закрыть экран Dx: вернитесь в приложение.
4. Убедитесь, что данные приняты, и нажмите **«Это нижняя кнопка»**. Старый отчёт сам не создаёт привязку.
5. Назначьте удержанию вибрацию, включите жест и выполните физическое удержание на включённом, разблокированном экране. Проверьте обычное короткое Back и верхнюю Home.
6. Для двойного/тройного откройте **«Настроить циферблат»**. После подтверждения проверяйте эти жесты на самом циферблате, каждый раз возвращаясь на него.

Экранная проверка действия выполняет команду напрямую и не проверяет физическое распознавание.

## Обновление и резервная копия

Release 1.1.0, 1.1.1-diagnostics и 1.1.2-ultra-test используют один сертификат. `adb install -r` обновляет такую установку без удаления данных. После диагностической версии Ultra **заново калибруйте кнопку**.

Debug подписан другим ключом. При `INSTALL_FAILED_UPDATE_INCOMPATIBLE` сначала экспортируйте настройки и сохраните JSON **за пределами данных приложения**. Только затем можно удалить debug и установить release. Удаление приложения удаляет его локальные файлы экспорта.

В **Настройки → Данные** доступны SAF-экспорт/импорт и текстовый редактор JSON, если на часах нет файлового провайдера. Импорт сбрасывает кнопку, профиль циферблата и режим перехвата: подтвердите их на текущем устройстве.

## Если что-то не работает

| Симптом | Что проверить |
|---|---|
| Служба выключена | Её статус в Dx и системных специальных возможностях; приложение не включает себя автоматически |
| Кнопка не определяется | Полную пару DOWN/UP и причину в «Отчёт кнопки»; конкурирующие key filters других служб |
| Отказ на Ultra | Модель, name, descriptor, id, event/device source, isVirtual и rejections в полном JSON; одного 264/580 недостаточно |
| Удержание работает, двойное нет | Подтверждение циферблата и отсутствие перехода в Wallet/Recents после Back |
| Жест виден, команда не работает | Результат команды, доступную Activity, разрешения и наличие выбранного пакета |
| Экран выключен / AOD | Обработка в этих состояниях отключена |
| ADB не отвечает | Текущий порт основного экрана отладки; он может измениться |

При необходимости получите только калибровочный журнал:

```sh
adb -s <WATCH_IP>:<CONNECTION_PORT> logcat -v threadtime -s DxButtonCalibration
```

Затем физически нажмите нижнюю кнопку во время калибровки. `adb shell input keyevent 264` — синтетический ввод, он не подтверждает аппаратную поддержку. Перед публикацией проверьте отчёт; полный системный logcat с личными данными не нужен.
