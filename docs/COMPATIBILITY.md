# Публичные API и границы совместимости

Обновлено 10 ноября 2026. Аппаратные испытания debug 1.1.0 выполнялись на Samsung SM-L355F, Android 17 / API 37. Новый профиль Ultra SM-L705 в 1.1.2 подготовлен по присланным фото и модели; физическая проверка нового APK ещё не выполнена. Совместимость не определяется по маркетинговому названию. Приложение сообщает `Build.MODEL`, Android API и `Build.DISPLAY`. Версии Wear OS / One UI Watch не угадываются из версии Android.

## Кнопки и сохранение штатного поведения

`canRequestFilterKeyEvents` и `FLAG_REQUEST_FILTER_KEY_EVENTS` запрашивают callbacks `AccessibilityService.onKeyEvent`. Наличие capability не подтверждает доставку физической кнопки. Фильтрацию может получить другая включённая служба. Калибровка требует аппаратную пару DOWN/UP, ненулевой scanCode, невиртуальный InputDevice и подтверждение пользователя.

Android требует согласованной фильтрации DOWN и UP. Нельзя пропустить DOWN системе, а после порога забрать только UP: получится повреждённая последовательность. Изменение копии KeyEvent не меняет системное событие. API не предоставляет инъекцию исходной физической последовательности без привилегий.

Поэтому режим по умолчанию — **наблюдение**: все DOWN/UP проходят системе. Одиночное нажатие сохраняется. Двойное/тройное выполняются дополнительно, только если весь жест произошёл на подтверждённом циферблате. Если одиночное действие Samsung уводит с циферблата, комбинация отменяется. Обойти это автоматически без изменения исходной семантики невозможно.

С версии 1.0.1 удержание по умолчанию запускается одноразовым таймером после DOWN, без перехвата системных событий. Это необходимо на исследованных часах, присылающих только DOWN/UP без повторов. Потерянный UP до порога неотличим от продолжающегося удержания и может вызвать ложное действие. Настройка «Запускать во время удержания» позволяет отключить таймер: тогда подтверждением служит повторный DOWN после порога либо совпадающий UP. Смена окна, выключение дисплея, блокировка и другая кнопка отменяют незавершённый жест. Недоступность дерева циферблата сама по себе глобальное удержание не блокирует; при настроенных исключениях неизвестное приложение блокирует его.

Дополнительный режим **перехват Back** доступен только после калибровки `KEYCODE_BACK`, явного выбора пользователя и назначения действия. Служба забирает всю пару; одиночный жест воспроизводится через `GLOBAL_ACTION_BACK`, при распознавании комбинации может задерживаться. Это не точное воспроизведение настройки Samsung «Недавние приложения». В этом режиме удержание выполняется по таймеру; потерянный UP до порога нельзя отличить от удерживания кнопки. При переходе окна, блокировке или второй аппаратной кнопке распознавание отменяется. Уже забранный DOWN вернуть системе нельзя. Режим не рекомендуется там, где необходимы системные сочетания с Back. Home/Power и STEM_PRIMARY не фильтруются.

Коды Back/STEM_1/STEM_2/STEM_3 принимаются после аппаратной пары и подтверждения. Home, Power, Sleep/Wake, громкость и системная навигация запрещены. Для `STEM_PRIMARY` сохранено прежнее исключение: аппаратное устройство `pmic_resin`, scan 580/114 и descriptor. С 1.1.2 добавлен отдельный проверочный профиль Samsung SM-L705: `gpio_keys`, только scan 580, event.source и InputDevice.sources 0x101, непустой descriptor, isVirtual=false и совпадение id. Требуются согласованная пара и подтверждение пользователя; профиль привязывается к фактически прочитанной модели. Другие модели и источники не разрешены. [Подробности и границы подтверждения Ultra](ULTRA_GPIO_PROFILE_1.1.2.md). На подключённом SM-L355F прочитана системная раскладка `/system/usr/keylayout/pmic_resin.kl`: оба scan сопоставлены STEM_PRIMARY; верхняя Power идёт с отдельного `pmic_pwrkey`. Эта привязка разрешена только в наблюдении, требует физического подтверждения нижней кнопки и не переносится импортом JSON. Неизвестный источник STEM_PRIMARY остаётся запрещённым.

## Samsung Pay, Wallet, Health

Samsung документирует запуск Pay удержанием Back на ряде Galaxy Watch. Публичный Android API не обещает отмену действия, уже перехваченного политикой прошивки. В наблюдении Wallet/Pay может открыться одновременно с командой Dx или изменить окно и отменить жест. Приложение не выключает, не удаляет и не заменяет пакеты Pay/Wallet.

В Samsung Health и сторонних тренировках аппаратные кнопки могут управлять тренировкой. Добавьте соответствующие пакеты в исключения удержания и сравните одиночное нажатие до/после включения Dx. Двойное и тройное вне циферблата отключены. Нижняя кнопка на некоторых моделях может иметь отдельную системную семантику; средняя Quick-кнопка не считается нижней автоматически. Достоверно универсального SDK для переназначения этих функций Samsung не публикует.

Экран выключен, AOD или Keyguard: обработка отключена. Ни получение key callback, ни снятие блокировки не имитируется. Служба не будит часы. При отключении службы пользователем Android не разрешает самостоятельно включить её обратно.

## Определение циферблата

Нет универсального публичного Android API «пользователь сейчас на основном циферблате». Текущий live wallpaper или package launcher сами по себе этого не доказывают: те же пакеты могут показывать шторки, плитки и список приложений. Современный Watch Face Format может рендериться системным хостом, а не пакетом автора циферблата.

`WatchFaceStateDetector` получает активное application-окно или system-окно хоста циферблата через публичные Accessibility API и ограниченно читает только package, class, resource ID, childCount, видимость и геометрию. Обход ограничен 32 узлами / глубиной 6 / 12 детьми узла. Внутренности поверхности `item_watchface` и деревья посторонних приложений не обходятся. Тексты, descriptions, extras, пароли и screenshot не читаются. Снимки метаданных, аппаратных устройств и состояния экрана обновляются отдельно от обработки кнопки. Перед клавишей и дедлайном используется только сохранённый снимок, без Binder-запросов и обхода дерева. Обновление запускается событиями окон и дисплея, без периодического опроса.

Автоматическое распознавание требует системный HOME-пакет, найденный через PackageManager, минимум два известных resource ID хоста и видимую поверхность циферблата, покрывающую не менее 85% дисплея. Поэтому сторонний циферблат, отрисованный системным хостом, тоже распознаётся. Package сам по себе не достаточен. Меню приложений, «Недавние», плитки и шторки не принимаются. Верхнее перекрывающее окно, блокировка и отсутствие данных запрещают жесты.

Калибровка сначала отправляет публичный GLOBAL_ACTION_HOME и через 900 мс проверяет доступные признаки циферблата. Если признаков нет, профиль не сохраняется. Для запасного пути совпадают package/class/root и устойчивые resource ID циферблата; точная геометрия и меняющиеся ID осложнений не сравниваются. SHA-256 остаётся в формате данных для совместимости, но не используется как условие распознавания. Старые профили «Недавние» отвергаются. Обязательно проверить отрицательные экраны. При пустых resource ID или недоступном root неизвестный хост отклоняется.

На API 33+ служба отключает системный кэш и предзагрузку Accessibility-узлов публичным `setCacheEnabled(false)`. Это предотвращает автоматическое обновление узлов на потоке callback при событиях содержимого, которые Dx не запрашивает. На более старых API этот метод недоступен; сохраняется ограниченное чтение метаданных. Версия 1.1.0 не выдаёт сокращение задержек одного callback за подтверждение надёжности всей последовательности: аппаратные результаты записываются отдельно.

## Действия

| Команда | Реализация и ограничение |
|---|---|
| Приложение | PackageManager: LAUNCHER, LEANBACK, INFO; только enabled/exported Activity с доступным permission. Без публичной Activity — честный отказ и пользовательский опубликованный ярлык |
| Home, Back, шторки, Recents, Lock, All Apps | Только опубликованные `service.systemActions`; проверяется ответ `performGlobalAction`. Прошивка Wear может не предоставлять часть команд |
| Таймер, будильники, календарь, диктофон, помощник | Стандартный Intent, `resolveActivity`, проверка Activity. Может отсутствовать на часах |
| Секундомер, поиск телефона, музыка | Выбранное установленное приложение; универсальные неподтверждённые vendor Intent не выдумываются |
| Play/Pause/Next/Previous | `MediaSessionManager.getActiveSessions`, проверка доступа NotificationListener и PlaybackState.actions; без чтения уведомлений и метаданных треков |
| Wi-Fi/Bluetooth/звук/энергосбережение | Разрешённые экраны Settings; защищённые тумблеры не меняются напрямую |
| Яркость | WRITE_SETTINGS special access, ручной режим + SCREEN_BRIGHTNESS, ответ ContentResolver. Фонарик использует только яркость своего Window |
| DND | ACCESS_NOTIFICATION_POLICY и `setInterruptionFilter`. На Android 15+ действует правило Dx; другие правила могут сохранять DND. Состояние отправленной команды хранится локально; ручные изменения системного правила вне приложения могут потребовать синхронизации |
| Пользовательский ярлык | URI Intent с разрешённым типом действия, доступной Activity; удалены selector, clipData и URI grant flags; нет CALL/SEND/служб или shell-команд |
| Последовательность | До 6 команд, предварительная проверка всей последовательности, остановка при ошибке, 180 мс между командами; асинхронный запуск Activity не подтверждает её готовность |

NotificationListener нужен только для получения MediaSession. Все категории доставки уведомлений отключены метаданными; код не обрабатывает notification callbacks. `QUERY_ALL_PACKAGES` нужен для локального каталога установленных приложений, включая пакеты без launch Activity. Публикация в Google Play требует обоснования широкого обзора пакетов и корректной декларации Accessibility; подписанные APK этого репозитория предназначены для установки вручную; Google Play-публикация не заявлена.
