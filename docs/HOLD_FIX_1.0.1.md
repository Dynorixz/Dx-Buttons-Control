# Удержание нижней кнопки: 1.0.1, 22 октября 2026

Исторический отчёт исправления в проекте `DxButtonsControl`.

## Причины и изменения

1. На подключённом Samsung SM-L355F нижняя кнопка передаёт `keyCode=264`, `scanCode=580`, `InputDevice.name=pmic_resin`. Старое приложение безусловно запрещало STEM_PRIMARY и не позволяло сохранить такую привязку. Теперь разрешён только проверяемый отдельный аппаратный источник `pmic_resin`, scan 580/114, непустой descriptor и невиртуальное устройство. Верхняя Power (`pmic_pwrkey`), Home и произвольный STEM_PRIMARY остаются защищёнными. Требуется подтверждение пользователя в калибровке. Вся последовательность проходит системе; режим захвата для этого источника запрещён.
2. Глобальное удержание ошибочно требовало доступного дерева активного окна. Теперь оно работает без дерева и без сигнатуры циферблата. Если настроены исключения, неизвестное активное приложение по-прежнему запрещает удержание.
3. При отсутствии повторных DOWN действие ожидало UP. Теперь один таймер запускает команду после порога (650 мс по умолчанию). Переключатель «Запускать во время удержания» позволяет вернуться к подтверждению повтором/UP. Таймер не может отличить потерянный UP от продолжающегося удержания; это ограничение прямо показано в настройке.
4. Исчезновение метаданных циферблата отменяет двойной/тройной жест, сохраняя независимое глобальное удержание в том же окне. Смена окна, выключение дисплея, блокировка и другая физическая кнопка отменяют удержание.
5. Во время обработки ключа и таймера не выполняется обход дерева Accessibility. Для работы одного удержания дерево вообще не запрашивается. Добавлены причины отказа в диагностике и отладочный тег `DxButtons` без содержимого экранов.

- Финальная инкрементальная сборка: `:app:assembleDebug :app:lintDebug --max-workers=2`. Успех; lint: 0 ошибок, 13 предупреждений.
- Проверены v2-подпись APK и zipalign с 16-КБ выравниванием.
- Версия 1.0.1 установлена через `adb install -r` с ответом `Success`; приложение запущено с `Status: ok`, служба включена пользователем и подключена, crashed services пусты.
- На реальных часах получена полная аппаратная последовательность. В журнале 13:27:48.482 — DOWN, 13:27:49.140 — единственный HOLD, 13:27:49.218 — успешный запрос запуска выбранного пользователем `me.thedise.mirpayinvoke`, 13:27:49.703 — UP. Действие запрошено до отпускания, примерно через 650 мс; повторных DOWN нет.
- Короткая последовательность с `eventTime-downTime=148 мс` не породила HOLD.

Пользователь подтвердил: «Удержание работает, короткое — как обычно». Эти испытания не подтверждают универсальную работу в AOD, при блокировке, во всех тренировках или отсутствие конфликта с Wallet на других прошивках. Двойной и тройной жесты в этом исправлении физически не проверялись.

Публичный контракт: [AccessibilityService.onKeyEvent](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService#onKeyEvent(android.view.KeyEvent)) требует согласованной фильтрации DOWN/UP. [KeyEvent](https://developer.android.com/reference/android/view/KeyEvent#KEYCODE_STEM_PRIMARY) описывает STEM_PRIMARY как основную кнопку питания: исключение здесь основано на фактически исследованном отдельном Samsung-источнике, а не на предположении по одному коду.
