# Участие в разработке

Для исправления создайте Issue или PR с конкретным сценарием, ожидаемым и фактическим результатом. Для нового аппаратного профиля нужны реальные данные кнопки: маркетинговое имя часов или один keyCode не подтверждают безопасную привязку.

## Перед PR

```sh
./gradlew :core:test :app:assembleDebug :app:lintDebug --max-workers=1 --console=plain
```

- Укажите модель, API, версию приложения и где проверялся физический жест.
- Отделяйте unit-тесты, передачу Intent и наблюдаемое действие на устройстве.
- Добавляйте тесты поведения для изменений автомата, безопасности и выполнения действий.
- Для новой кнопки нужны полная пара DOWN/UP и InputDevice-поля. Не публикуйте посторонние личные данные.
- Не разрешайте STEM_PRIMARY без подтверждённого профиля и не ослабляйте Home/Power.
- Сохраняйте целостную семантику DOWN/UP, ограниченное чтение метаданных и событийный фон без polling.
- Обновляйте совместимость и заметки релиза при изменении границ поведения.

[План физических испытаний](docs/DEVICE_TEST_PLAN.md) включает положительные и отрицательные экраны. Не проверяйте экстренные сочетания экспериментальным перехватом.

## Что не коммитить

SDK-пути, настройки устройств, полный logcat, клиентские JSON, подписи/пароли, SDK, кэши, результаты сборки и машинные резервные копии. Подписанные установщики размещаются в Releases, а не в истории Git.

Секреты не присылайте в Issue/PR. Для уязвимостей используйте [SECURITY.md](SECURITY.md). Отдельная лицензия на повторное использование исходников пока не выбрана.
